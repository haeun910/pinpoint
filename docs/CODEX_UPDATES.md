# Codex 공고 갱신

목표: IT/AI 채용·청년 지원·공모전을 정리하고 청약은 분야 제한 없이 유지한다.

## 멀티 에이전트 실행

사용자는 3역할 멀티 에이전트 진행을 요청했다. 공고 확인 에이전트는 검색·원문 검증 결과를 구조화해 반환한다. 분류 에이전트는 검증된 자료를 읽고 IT/AI 관련성과 지원 조건·기한을 분류한다. 추천 에이전트는 신입·인턴·입문 교육을 선호하는 사용자에게 유용한 이유와 확인할 조건을 작성한다. 나이·학력·거주지는 미상이며 지원 가능 여부를 단정하지 않는다. 독립적인 출처 조사는 병렬화하고, 분류와 추천은 확인된 결과를 입력으로 받는다. 사이트 소스·배포·쓰기 작업은 소유 에이전트 한 명이 맡아 충돌을 피한다. 멀티 에이전트 도구가 없으면 그 제한을 보고하며 병렬 실행했다고 주장하지 않는다.

## 자료 갱신

1. 연결된 Pinpoint의 `get_notices` 도구를 호출해 기존 데이터, revision, sourceDefinitions, updateGuide를 읽는다. 도구가 보이지 않으면 Sites `get_site`에서 이 사이트의 서비스 접근 자격을 다시 얻는다. 토큰을 소스·로그·작업 지침에 저장하지 않는다.
2. 웹 검색과 원문 열기로 신규 공고와 기존 공고의 일정 변경·마감을 확인한다. 지원 기간, 대상, 지역, 공고 원문 URL과 확인 날짜를 기록한다. 목록 게시 종료일을 신청 마감일로 단정하지 않는다.
3. 제목·실제 직무가 IT/AI인 채용·공모전·청년 지원만 수록한다. 회사 이름, incidental AI 우대 사항으로 일반 직무를 넣지 않는다. 청약은 IT/AI 제한을 적용하지 않는다.
4. 같은 공고는 기존 id를 유지한다. `upsert_notices`에 현재 revision, 확인한 items, 실제 조사한 checkedSources를 전달한다. 확인 수준은 원문 detail, 목록 listing, 검색 search로 기록하고 확인 못한 마감일은 null로 둔다. 확인 실패한 기존 공고를 삭제하지 않는다.
5. 다시 `get_notices`를 호출해 ID·변경 내용·revision을 확인한다. 충돌이면 다시 읽고 병합한다. 갱신에 실패하면 성공으로 보고하지 않는다.

MCP 대체 경로: 소유자 전용 Site의 `GET /api/notices`, `GET /api/update-guide`, `POST /api/updates`를 사용한다. 각 요청은 get_site에서 얻은 자격을 **해당 Pinpoint 호스트에만** OAI-Sites-Authorization 헤더로 전달한다. 공개 사이트로 변경될 경우 쓰기 권한 설계를 별도로 검토해야 한다.

일상 데이터 갱신에는 재배포가 필요 없다. 기능 변경은 GitHub `1015` 브랜치와 구체적인 한글 커밋을 사용한다.
